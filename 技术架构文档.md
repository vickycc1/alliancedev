## 一、架构概述

### 1.1 架构目标

| 目标 | 描述 |
|------|------|
| 高可用 | 系统可用性 ≥ 99.5%，单点故障不影响整体服务 |
| 高性能 | API平均响应 ≤ 500ms，支持500用户并发在线 |
| 可扩展 | 模块化设计，支持水平扩展和功能扩展 |
| 安全性 | 传输加密、存储加密、权限控制、内容合规 |
| 可维护 | 代码分层清晰，模块职责单一，便于迭代维护 |

### 1.2 架构原则

| 原则 | 说明 |
|------|------|
| 分层架构 | 前后端分离，后端严格分层（Controller → Service → Mapper） |
| 单一职责 | 每个模块/类只负责一项功能 |
| 接口抽象 | 核心组件面向接口编程，便于替换实现（如AI服务、存储服务） |
| 防御性编程 | 所有外部输入均需校验，所有异常均需捕获处理 |
| 幂等设计 | 写操作接口幂等，防止重复提交 |
| 异步解耦 | 耗时操作（AI调用、通知推送）异步处理，不阻塞主流程 |

### 1.3 架构风格

```
整体架构风格：单体应用 + 模块化分层
前端架构风格：SPA（单页应用）+ 组件化
数据架构风格：关系型数据库 + 缓存 + 异步消息
通信架构风格：RESTful API + WebSocket + SSE
```

> 当前阶段采用单体架构，模块化设计为未来微服务拆分预留边界。

### 2.2 请求处理链路

```
用户请求
  → Nginx（SSL终结 + 路由分发）
    → /api/* → Spring Boot 后端
    → /*     → React SPA 静态资源
      → Spring Boot
        → CorsFilter（跨域处理）
        → JwtAuthenticationFilter（JWT认证）
        → CasAuthenticationFilter（CAS认证）
        → Spring Security（权限校验）
        → Controller（参数校验 + 请求分发）
        → Service（业务逻辑）
          → Mapper（数据访问）
          → RedisTemplate（缓存读写）
          → AiService（AI接口调用）
        → Result<T>（统一响应封装）
  → 用户
```

### 4.2 Docker Compose 部署方案

```yaml
version: '3.8'
services:
  nginx:
    image: nginx:1.25
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./nginx/conf.d:/etc/nginx/conf.d
      - ./frontend/dist:/usr/share/nginx/html
    depends_on:
      - backend

  backend:
    build: ./backend
    ports:
      - "8080:8080"
    environment:
      - SPRING_PROFILES_ACTIVE=prod
      - DB_HOST=mysql
      - REDIS_HOST=redis
      - AI_API_KEY=${AI_API_KEY}
      - JWT_SECRET=${JWT_SECRET}
    depends_on:
      - mysql
      - redis

  mysql:
    image: mysql:8.0
    ports:
      - "3306:3306"
    environment:
      - MYSQL_ROOT_PASSWORD=${DB_PASSWORD}
      - MYSQL_DATABASE=tech_community
    volumes:
      - mysql_data:/var/lib/mysql
      - ./backend/src/main/resources/db/schema.sql:/docker-entrypoint-initdb.d/schema.sql

  redis:
    image: redis:7-alpine
    ports:
      - "6379:6379"
    volumes:
      - redis_data:/data

volumes:
  mysql_data:
  redis_data:
```

## 五、后端架构设计

### 5.1 分层架构

```
┌─────────────────────────────────────────────────────┐
│                   Controller 层                      │
│  职责：参数校验、请求分发、响应封装                      │
│  规范：                                             │
│    - 使用 @Validated 进行参数校验                     │
│    - 统一返回 Result<T>                              │
│    - 不包含业务逻辑                                   │
│    - 使用 DTO 接收请求和返回响应                       │
├─────────────────────────────────────────────────────┤
│                   Service 层                         │
│  职责：核心业务逻辑、事务管理、流程编排                  │
│  规范：                                             │
│    - 面向接口编程（Service接口 + ServiceImpl实现）     │
│    - 复杂业务使用 @Transactional 事务管理             │
│    - 调用 Mapper 层进行数据访问                       │
│    - 调用其他 Service 进行业务编排                    │
│    - 抛出 BusinessException 业务异常                 │
├─────────────────────────────────────────────────────┤
│                   Mapper 层                          │
│  职责：数据访问、SQL映射                              │
│  规范：                                             │
│    - 继承 BaseMapper<T>                              │
│    - 复杂查询使用 XML 映射或 @Select 注解             │
│    - 不包含业务逻辑                                   │
├─────────────────────────────────────────────────────┤
│                   Entity 层                          │
│  职责：数据库实体映射                                 │
│  规范：                                             │
│    - 使用 @TableName 映射表名                        │
│    - 使用 @TableId 映射主键                          │
│    - 使用 @TableField 映射字段                       │
│    - 不包含业务方法                                   │
└─────────────────────────────────────────────────────┘
```

#### 5.3.3 全局异常处理器

```java
@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(BusinessException.class)
    public Result<?> handleBusinessException(BusinessException e) {
        return Result.error(e.getCode(), e.getMessage());
    }

    @ExceptionHandler(MethodArgumentNotValidException.class)
    public Result<?> handleValidationException(MethodArgumentNotValidException e) {
        String message = e.getBindingResult().getFieldErrors().stream()
            .map(FieldError::getDefaultMessage)
            .collect(Collectors.joining("; "));
        return Result.error(400, message);
    }

    @ExceptionHandler(AccessDeniedException.class)
    public Result<?> handleAccessDeniedException(AccessDeniedException e) {
        return Result.error(403, "无权限访问");
    }

    @ExceptionHandler(Exception.class)
    public Result<?> handleException(Exception e) {
        log.error("系统异常", e);
        return Result.error(500, "服务器内部错误");
    }
}
```

```typescript
const apiClient = axios.create({
  baseURL: import.meta.env.VITE_API_BASE_URL,
  timeout: 30000,

apiClient.interceptors.request.use((config) => {
  const token = useAuthStore.getState().token;
  if (token) {
    config.headers.Authorization = `Bearer ${token}`;
  }
  return config;
});

apiClient.interceptors.response.use(
  (response) => {
    const result = response.data;
    if (result.code !== 200) {
      message.error(result.message);
      if (result.code === 401) {
        useAuthStore.getState().logout();
        window.location.href = '/login';
      }
      return Promise.reject(new Error(result.message));
    }
    return result.data;
  },
  (error) => {
    if (error.response?.status === 401) {
      useAuthStore.getState().logout();
      window.location.href = '/login';
    }
    return Promise.reject(error);
  }
);
```

### 8.1 缓存策略

| 缓存对象 | Key格式 | 过期时间 | 更新策略 | 说明 |
|---------|---------|---------|---------|------|
| 用户信息 | `user:info:{userId}` | 30min | 写时更新 | 登录后缓存，修改时清除 |
| 板块树 | `category:tree` | 1h | 写时更新 | 板块变更频率低 |

| 未读通知数 | `notification:unread:{userId}` | 无过期 | 实时更新 | WebSocket推送时更新 |
| 敏感词库 | `sensitive:words` | 24h | 手动刷新 | 管理员更新时刷新 |
| 接口限流计数 | `ratelimit:{userId}:{action}` | 1h | 滑动窗口 | 限流计数器 |

### 8.2 缓存一致性

```
写入策略：Cache-Aside Pattern
  - 读：先查缓存 → 缓存未命中 → 查数据库 → 写入缓存
  - 写：先更新数据库 → 再删除缓存

防缓存穿透：
  - 查询不存在的数据，缓存空值（TTL 5分钟）

防缓存雪崩：
  - 缓存过期时间添加随机偏移（基础时间 ± 10%）

防缓存击穿：
  - 热点数据使用互斥锁更新（Redis SETNX）
```

### 9.2 JWT Token 设计

```
JWT 结构：
  Header:  { "alg": "HS256", "typ": "JWT" }
  Payload: {
    "sub": "userId",           # 用户ID
    "username": "zhangsan",    # 用户名
    "roles": ["USER"],         # 角色列表
    "iat": 1715000000,         # 签发时间
    "exp": 1715086400          # 过期时间（24h）
  }
  Signature: HMACSHA256(base64(header) + "." + base64(payload), secret)

Token 存储：
  - Access Token：前端 localStorage，每次请求通过 Authorization Header 携带
  - Refresh Token：前端 localStorage，用于无感刷新 Access Token

Token 刷新策略：
  - Access Token 有效期 24 小时
  - Refresh Token 有效期 7 天
  - 前端检测 Access Token 即将过期（距过期 < 5分钟），自动调用刷新接口
  - 刷新接口验证 Refresh Token 有效后，颁发新的 Access Token 和 Refresh Token
```

```java
@GetMapping(value = "/api/ai/stream/{postId}", produces = MediaType.TEXT_EVENT_STREAM_VALUE)
public SseEmitter streamAiResponse(@PathVariable Long postId) {
    SseEmitter emitter = new SseEmitter(120000L); // 2分钟超时

    aiService.streamGenerate(postId, new SseEmitterCallback() {
        @Override
        public void onToken(String token) {
            try {
                emitter.send(SseEmitter.event().data(token));
            } catch (IOException e) {
                emitter.completeWithError(e);
            }
        }

        @Override
        public void onComplete(String fullContent) {
            emitter.send(SseEmitter.event().name("complete").data("[DONE]"));
            emitter.complete();
        }

        @Override
        public void onError(Exception e) {
            emitter.send(SseEmitter.event().name("error").data(e.getMessage()));
            emitter.completeWithError(e);
        }
    });

    return emitter;
}
```

## 十五、高可用与容灾

### 15.1 高可用设计

| 组件 | 高可用方案 |
|------|-----------|
| Nginx | 主备模式，Keepalived VIP切换 |
| Spring Boot | 多实例部署，Nginx负载均衡（轮询/加权） |
| MySQL | 主从复制，读写分离，主库故障手动提升从库 |
| Redis | 哨兵模式（Sentinel），自动故障转移 |

### 15.2 容灾策略

| 场景 | 应对方案 |
|------|---------|
| 数据库主库宕机 | Sentinel自动提升从库为主库，应用切换连接 |
| Redis宕机 | Sentinel自动故障转移，缓存降级直接查数据库 |
| AI接口不可用 | 降级处理：隐藏AI回答入口，帖子正常使用 |
| CAS服务不可用 | 降级处理：仅允许账号密码登录 |
| 磁盘故障 | 数据库每日全量备份 + 实时Binlog备份 |

### 15.3 数据备份策略

| 备份类型 | 频率 | 保留周期 | 存储位置 |
|---------|------|---------|---------|
| 数据库全量备份 | 每日 02:00 | 30天 | 异地存储 |
| 数据库增量备份 | 每小时 | 7天 | 异地存储 |
| Redis RDB | 每6小时 | 7天 | 本地 + 异地 |
| 上传文件备份 | 每日 | 30天 | 异地存储 |

### 16.1 监控体系

| 监控维度 | 监控项 | 工具 |
|---------|--------|------|
| 应用监控 | API响应时间、错误率、QPS | Spring Boot Actuator + Prometheus |

| 业务监控 | 发帖量、评论量、AI调用次数 | 自定义埋点 |

### 16.2 日志规范

```
日志框架：SLF4J + Logback

日志级别：
  - ERROR：系统错误，需要立即处理
  - WARN：潜在问题，需要关注
  - INFO：关键业务操作（登录、发帖、AI调用等）
  - DEBUG：调试信息（开发环境）

日志格式：
  [时间] [级别] [TraceId] [类名] - 日志内容

关键日志埋点：
  - 用户登录/登出
  - 帖子发布/编辑/删除
  - AI接口调用（请求/响应/耗时/Token消耗）
  - 异常堆栈
  - 限流触发
  - 敏感词拦截
```

### 16.3 健康检查

```
Spring Boot Actuator 端点：
  - /actuator/health    → 应用健康状态
  - /actuator/info      → 应用信息
  - /actuator/metrics   → 指标数据
  - /actuator/prometheus → Prometheus格式指标

健康检查项：
  - 数据库连接状态
  - Redis连接状态
  - 磁盘空间
  - AI接口可用性
```

## 十七、技术风险与应对

| 风险项 | 风险等级 | 影响 | 应对措施 |
|--------|---------|------|---------|
| AI接口响应慢 | 高 | 用户等待体验差 | SSE流式输出+异步处理+超时控制 |
| AI接口不可用 | 高 | AI回答功能不可用 | 降级处理：隐藏AI入口，帖子正常使用 |
| AI回答内容违规 | 中 | 违规内容展示 | 内容合规校验+敏感词过滤+人工举报审核 |
| 高并发写入 | 中 | 数据库压力大 | Redis缓存+异步写入+读写分离 |
| 富文本XSS攻击 | 高 | 安全漏洞 | 服务端XSS过滤+白名单机制+CSP策略 |
| CAS单点故障 | 中 | 无法CAS登录 | 保留账号密码登录作为降级方案 |
| 数据库主库故障 | 高 | 写入不可用 | 主从复制+手动切换+数据备份恢复 |
| Token泄露 | 中 | 账号被盗 | HTTPS传输+HttpOnly+短期有效期+刷新机制 |
| 敏感词误判 | 低 | 正常内容被拦截 | 人工审核申诉通道+敏感词库持续优化 |
| 存储空间不足 | 低 | 文件上传失败 | 磁盘监控+容量告警+定期清理 |
